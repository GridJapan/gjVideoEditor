# レンダラ（renderer/render.py）の作法

Pillow（字幕・図形）＋ ffmpeg（映像/音声の合成）。**書き出しの正はここ**。

## 触るな系（実測で決めた値）

### zoompan のスーパーサンプリング

入力を **動的に2/4/8倍**へ拡大してから zoompan にかけている。

zoompan は切り出し座標を**入力解像度の整数pxに丸める**ため、精度が足りないと1pxずつ跳んで
「小刻みな揺れ」になる。必要精度は**ズーム量×クリップ長**で決まる。

2026-07-23実測: 切り出し移動 0.89px/frame=滑らか / 0.44=軽い跳び / 0.22=ジッタ（静止フレーム41%）。

→ 「**0.8px/frame以上になる最小倍率**」をクリップごとに計算する。
**しきい値0.8を下げないこと。** 遅く長いズームは自動で8倍が選ばれる。

出力は等倍（旧: 2倍→縮小。ジッタ・画質とも実測同等で、速度が非線形に改善）。
効果: 38.4秒動画の書き出し 310秒 → **33秒**（issue #2）。

### 音声

- **ラウドネス正規化は既定ON**（loudnorm -14 LUFS / TP -1.5、YouTube想定）。
  無効化は `{"op":"setroot","key":"audio","merge":{"loudnorm":{"on":false}}}`。
  シングルパスなので実測±1.5LU程度は誤差
- **全音声ピースに8msマイクロフェード自動付与**（ジャンプカット境界のプチノイズ防止。明示fadeIn/Outと共存）
- `in`（ソース内オフセット）は**映像と音声の両方**で読む。片方だけ対応するとズレる
- **amix直後の `asetpts=N/SR/TB` は省略禁止。** atempo（`speed`）のPTSが非単調のまま
  AACエンコーダへ届くと、**エラーを出さずに音声が途中で切れる**
  （2026-08-06実測: 倍速クリップの開始時刻で音声が終わり stream duration が 0.01s になった）
- **ダッキング**は `duck_expr()` が volume の t 式を作る（`duck:true` → ナレーション区間で0.25へ・0.35秒で滑らかに）。
  相手は render 内でトラックから付与する `_tid`/`_tlabel` で探す
- ⚠️ **音量の検証で mp4 を直接 `-ss <t> -i` して volumedetect しない。**
  AACでは正しく測れず「全区間同じ値」に見える（2026-08-06、これで誤診しかけた）。
  **音声を丸ごと wav に抜いてから**区間を測ること
- デバッグ: `VE_KEEP_FC=1` で `_fc.txt`（フィルタグラフ）を残し、実行コマンドを stderr へ出す

### 画像・映像の新属性（2026-08-06 追加）

| 属性 | 対象 | 実装 |
|---|---|---|
| `fadeIn`/`fadeOut` | 画像 | アルファfade。静止1フレームでは動かないため **`-loop 1` で連続フレーム化**（Ken Burns時はzoompanが生成するので不要） |
| `opacity` | 画像 | colorchannelmixer=aa |
| `motion.pan` | 画像 | zoompanのx/y式。**パン単独はズーム固定1.1で全域横断**、zoom併記ならズームしながら流れる |
| `speed` | 映像 | `setpts=PTS/speed` + atempo連結。**ソースは vdur×speed 消費**（入力-tも逆算） |
| `duck` | 音声 | 上記ダッキング |
| `adjust`{brightness,contrast,saturation} | 画像・映像 | **意味はCSS filterに揃える**（プレビューと一致させる取り決め）。画像=PIL `apply_color`（アルファ保持） / 映像=colorchannelmixer(乗算輝度)+eq。**ffmpegのeqはアルファを壊すため画像に使わない**。キー名が `adjust` なのは `color` が字幕の旧文字色で使用済みのため |
| `flip` | 画像・映像 | 左右反転。画像=PIL transpose / 映像=hflip（回転より先に掛ける） |
| `loop` | 音声 | `-stream_loop -1`。**ソース長検査が免除される唯一の例外**（BGMが尺より短いとき用） |

- **無音の映像ソース（画面収録など）を `[N:a]` で参照しない。** `matches no streams` で
  グラフ構築ごと落ちる（2026-08-06実測）。`has_audio_stream()` が事前に見てスキップする
- **区間書き出し**: `render.py <pdir> --range A B` → `out/<title>_A-Bs.mp4`。
  出力側 -ss なので合成結果はフル書き出しと同一。マスターは別名のまま潰さない

### 字幕

- **`render_caption_image()` が字幕描画の唯一の実装。** UIのプレビューもこれを呼ぶ（`/api/caption-preview`）。
  ここを分岐させるとプレビューと書き出しが食い違う
- **自動折り返しは禁則処理つき**: 英数字・記号の連なり（HDMI・(2010)等）は分断しない／
  行頭に「、。」等は来ない（ぶら下げ）／行末に開き括弧は残らない。
  ただし和文の文節までは見ないので、**見出し級の大テロップは明示 `\n` で改行するのが確実**

## 出力は一時ファイル経由で差し替える

`out/名前.mp4` へ直接書かない。ffmpeg は**開いた時点で中身を切り詰める**ため、
途中で失敗・中断すると数十バイトの再生不能ファイルが残る。しかも mtime は新しいので
サーバの鮮度判定を通り、次の書き出しが壊れたファイルを "成功" として返す（実際に起きた）。

→ `.名前.rendering.mp4` に書き、`returncode==0` かつ `getsize>0` のときだけ `os.replace()`。
失敗・中断時は一時ファイルを消す。

## project.json は信用できない入力として扱う

zip読み込み（`/api/import-project`）で他人から受け取ったものがそのまま来る。
**ffmpeg のコマンドラインやパスに載る値は必ず検証してから使う。**

- `canvas.bg` → `safe_color()`。素通しすると `black:s=8x8,nullsink;color=c=blue` のように
  **任意のフィルタチェーンを追加実行できた**（`movie=` でローカルファイル読み込みも可能だった）
- `meta.title` → `safe_title()`。素通しすると `../../名前` で projects/ の外へ書き出せた

新しく外部値をコマンドラインへ載せるときは、同じように検証関数を通すこと。

## エラーは stderr へ

ffmpeg の失敗内容は `print(..., file=sys.stderr)` で出す。
stdout に流すと `ui/server.py` が `r.stderr` しか拾わず、ブラウザには「書き出し失敗: 500」しか
出ないため原因が追えなくなる。

**素材が無い時は黙って進めない。** 映像・画像・音声をまとめて実在チェックし、
人間可読エラー（種別・ファイル名・対処3案）で止める。生のffmpeg英語エラーを出さない。

## フォント

ヒラギノ → 游ゴシック/メイリオ の順で自動解決（`WIN_GOTHIC` 等）。
**Mac専用パスを決め打ちしない**（Windowsで日本語が豆腐になる）。

- 候補は `"パス"` か **`"パス#N"`**（`.ttc` 内のフェイス番号）。
  太さが別ファイルでなく同一ttcの別フェイスにあるフォントがある
  （`Hiragino Sans GB` は W3=0 / **W6=2**。index未指定だと常に細字）
- **簡体字は `Hiragino Sans GB`**（Winは Microsoft YaHei へ落ちる）。
  日本語フォントは「饺・实・铺」等のグリフを持たない
- **`missing_glyphs(font, text, bold)` で描けない文字を事前に検出できる。**
  未定義コードポイント(U+10FFFF)の描画結果と各文字を突き合わせる方式なので、
  フォント名やOSに依存しない。`tools/patch.py --check` がこれを呼ぶ
  （2026-08-03: 中国語字幕で「饺子咖喱」が「□子□□」になり書き出し直しになった）

## 字幕のアニメーション

| `anim` | 中身 | 実装 |
|---|---|---|
| `pop` | スタンプ。1.9倍→等倍を0.16秒（ease-in＝着地直前が最速） | 静止pngを `-loop 1` で連続フレーム化し scale の t 式で拡縮 |
| `countup` | **金額が 0 → 実値へカウントアップ** | 画そのものが変わるので**連番PNG**。`tpad=stop_mode=clone` で最終フレームを引き延ばす |
| `typewriter` | 1文字ずつ出す | 同上（連番PNG） |
| `slide` | 画面外から滑り込む（`slideFrom`: left/right/top/bottom） | overlay の x/y を t 式で動かすだけ。**連番PNG不要で軽い** |

`bar`（比較バー）は anim ではなくクリップのプロパティ。字幕の下に横棒を敷き、`ratio`(0〜1)
の長さで差を見せる。**`countup` と併用すると数字と一緒に伸びる**。
数字だけを読ませるより「$139=満タン / $10=7%」と並べたほうが差が一撃で伝わる。

**連番PNG系（`countup`/`typewriter`）は `SEQ_ANIMS` にまとめてある。** 増やすときはここに足す。

`countup` の作法:

- **既定は金額（`$139` / `22,000円` / `¥500`）だけ動く。** 全数値を動かすと順位の `#2` や
  `10 min` まで数え上がって意味が壊れる（2026-08-05に実際に `#1→#2` とカウントした）。
  全部動かしたいときだけ `countAll: true`
- **座布団の幅は最終形で固定する**（`_widthText`）。毎フレーム文字幅で描くと箱が伸縮してガタつく
  （`typewriter` も同じ。文字が増えるたび箱が広がると読みにくい）
- イージングは ease-out。着地でゆっくり止まり「数字が決まる」感じになる

## 書き出しコーデック

`libx264` を決め打ちしない。**`pick_video_codec()`** が ffmpeg に問い合わせ、
実在するものを選ぶ（libx264 → libopenh264 → h264_videotoolbox → mpeg4）。
配布ビルドによっては libx264 が無く、決め打ちだと配布先で「書き出しだけ落ちる」になる。
`VE_VIDEO_CODEC=<name>` で明示指定もできる。
